# ЛР5. Границы данных и приватность

Район 1 «Шлюз»

## Каталог данных

Каталог `config/privacy.toml` описывает допустимые поля и основания обработки. SOC получает уведомление о блокировке источника. Для разбора достаточно кода причины и псевдонимов для сопоставления записей.

| Поле | Категория | Основание |
|---|---|---|
| `actor_id` | `pseudonym` | Связать действия одной административной учётной записи при расследовании. |
| `source` в `data` | `pseudonym` | Сопоставить повторные блокировки одного источника. |
| `block_id` | `open` | Случайный идентификатор правила для сверки с уведомлением. |
| `reason_code` | `open` | Фиксированные коды `abuse`, `scan`, `policy` различают причины блокировки. |
| `status` | `open` | Значение `ok` в учебной проверке границы. |
| `reason` | `forbidden` | Свободный текст может содержать идентификаторы и адреса. |
| `authorization` | `forbidden` | Заголовок авторизации даёт доступ от имени пользователя. |
| `request_body` | `forbidden` | Тело запроса может содержать произвольные ПДн и секреты. |
| `debug_context` | `forbidden` | В диагностический контекст могут попасть заголовки и параметры запроса. |

Поле `source` в конверте содержит адрес сервиса Шлюза. Поле `data.source` содержит псевдоним адреса заблокированного источника. `subject` — случайный UUID, совпадающий с подписанным полем `data.block_id`.

## Фильтр и подпись

`privacy/boundary.py`, метод `Boundary.filter_event`, проверяет конверт и полезную нагрузку. Каждое поле нужно явно разрешить в каталоге. Открытые поля ограничены форматом UUID или перечислением. Для полей категории `pseudonym` фильтр вычисляет `psn:` и первые 32 шестнадцатеричных символа HMAC-SHA256 от имени поля, перевода строки и значения. Для HMAC используется собственная случайная соль Шлюза длиной 32 байта. Соответствия записываются в локальную SQLite-базу после проверки всего события.

Продюсер передаёт в подпись `citysig` и очередь доставки результат фильтра. При отказе границы журнал сообщает об отклонении. В очереди нет исходного содержимого отклонённого события. `python scripts/check-privacy.py` проверяет девять требований на синтетических данных, включая подпись и содержимое фактической очереди. Для полного прогона обмена используйте команды из [README](../README.md).

## Границы

Прогноз для фильтра из учебной заготовки — неизвестное поле с диагностическими данными уйдёт в событии без преобразования, поскольку заготовка пропускает поля без записи в каталоге.

Факт местного прогона на синтетических строках — событие с полем `debug_extra`, которого нет в каталоге, отклонено с кодом `unknown_field`. Событие с явно запрещённым `debug_context` отклонено с кодом `forbidden_field`. В обоих случаях локальная таблица не создалась даже при наличии `actor_id`, которое фильтр встретил раньше. Для диагностики в каталоге зафиксировали категорию `forbidden` и причину. Новый неизвестный ключ фильтр тоже отклонит.

## Вопросы ЛР5

1. Если подписать данные до фильтрации, замена исходного `source` псевдонимом меняет `data`, и получатель отвергает подпись. При попытке устранить отказ отправкой исходного пакета адрес попадёт в шину. Подпись рассчитана по тому же очищенному содержимому, которое проверяет получатель.
2. Если два района возьмут один ключ для одинакового поля и значения, псевдонимы совпадут. Наблюдатель сможет склеить их журналы и связать события одного жителя между районами. Собственная соль каждого района и имя поля в HMAC ограничивают такую корреляцию.
3. Чтобы исполнить запрос жителя за рабочий день, оператору нужен перечень мест хранения, доступ к локальной таблице и понятная процедура сверки личности. В `docs/recovery.md` описан порядок удаления исходных значений и обработки копий. Удаление строки прекращает восстановление внутри Шлюза. Псевдонимы, уже доставленные другим районам, удаляются по процедурам их владельцев.
