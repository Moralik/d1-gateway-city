# Восстановление района №1 «Шлюз»

## Зависимости

- Git, Docker Engine и Docker Compose v2. Python 3.12+ нужен для локальных проверок.
- Git-репозиторий или `git bundle` из `scripts/pack.sh`. Архив содержит код и документацию.
- Для восстановления состояния подготовьте согласованный снимок томов `db-data`, `gateway-state` и `broker-state`. Остановите сервисы перед файловым копированием SQLite либо сделайте согласованный бэкап через SQLite API. Очередь, дедупликацию и состояние брокера восстанавливайте из одной точки.

## Секреты

- Восстановите `.env` из закрытого хранилища. Нужны `DB_PASSWORD`, ключи `BUS_SECRET` и `BUS_CONSUME_SECRET`, `PRIVACY_SALT` и токен `GATEWAY_ADMIN_TOKEN`. У источника и получателя должно совпадать значение ключа для соответствующего направления.
- Для городского TLS восстановите `tls/private/district.key` из закрытого хранилища или запросите перевыпуск сертификата через городской УЦ. Восстановите значение `DISTRICT_HOST` для городского стенда.
- Восстановление прежней соли нужно для сопоставления существующих записей. При смене соли рабочие псевдонимы и правила блокировки требуют согласованной миграции.

## Порядок запуска

1. Клонируйте репозиторий или `git clone d1-gateway.bundle d1-gateway`. Восстановите `.env`.
2. Подготовьте тома, не запуская сервисы. `docker compose -f compose.yaml -f compose.labs.yaml create --build` создаст контейнеры и тома. Если нужен TLS, добавьте `-f compose.tls.yaml` к списку файлов.
3. Восстановите согласованный снимок в соответствующие пустые тома с сохранением владельцев файлов. SQLite-тома API и брокера обслуживает UID `10001`. Пропустите этот шаг при чистом запуске лаборатории.
4. Выполните `docker compose -f compose.yaml -f compose.labs.yaml up --build -d` с тем же набором файлов. При недоступном брокере API сохраняет события и повторяет отправку.

## Проверка после восстановления

1. Проверьте `/health` по опубликованному адресу и состояние контейнеров через `docker compose -f compose.yaml -f compose.labs.yaml ps`.
2. Проверьте, что очередь разгружается. В журнале API ожидаются `event.published` для доставленных событий и `event.consumed` для принятых инцидентов.
3. На отдельном тестовом стенде запустите `python scripts/check-bus.py` и `python scripts/check-privacy.py`.
4. Если подключён TLS, выполните `bash scripts/check-tls.sh gateway 8443 80` с городским корнем доверия.

## ПДн

Соответствия псевдонимов и исходных значений находятся в отдельном локальном томе `gateway-private` по пути `/var/lib/gateway/private/vault.sqlite3`. При запуске без Docker хранилище создаётся в `local/vault.sqlite3`. Доступ имеют процесс API и уполномоченный оператор района. В контейнере каталог и файл имеют права `0700` и `0600`. Резервная копия таблицы хранится отдельно с теми же ограничениями доступа.

Уполномоченный оператор сверяет запрос и запускает `docker compose -f compose.yaml -f compose.labs.yaml exec api python -m privacy delete source`. Исходное значение вводится в скрытом приглашении. Для других полей используется соответствующее имя из каталога. Оператор проверяет отсутствие восстановления, отмечает запрос без записи исходного значения и применяет то же удаление к восстанавливаемым копиям в рамках регламента. Цель выполнения запроса — один рабочий день. Срок хранения соответствий — 30 дней. Команда `python -m privacy purge` удаляет просроченные строки из доступного локального хранилища.
